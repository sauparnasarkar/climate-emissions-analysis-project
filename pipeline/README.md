# `pipeline/` — Area 2 ingestion (Release 21, Phase 1.1)

Versioned ingestion scripts for the climate-context sources, one module per source, writing
normalized series to `data/climate/` (gitignored) plus provenance. Not intern curriculum and not
`api/` runtime code — see `SPEC.md` §5.26 and `ENHANCEMENTS.md` Release 21.

```
python -m pipeline.run                      # all ACTIVE (publishable) sources
python -m pipeline.run --source noaa_gml    # or berkeley_earth, primap_hist, owid, harmonize
python -m pipeline.run --source edgar       # shelved source: explicit opt-in, writes to data/internal/edgar/ only
.venv/bin/python -m pytest pipeline/tests   # offline; no network
```

or odd source is a *deviation* (warning) the refresh job turns into an alert.

### PRIMAP-hist notes

- **Why PRIMAP-hist:** it replaces EDGAR as the total-GHG / composition / country-share source because EDGAR's IEA-sourced fuel-combustion CO₂ is CC BY-NC-ND 4.0 (`ENHANCEMENTS.md` Release 21, decisions 20–21). PRIMAP-hist is **CC BY-NC-SA 4.0** (since v2.8; the dataset's YAML says Attribution-NonCommercial — the authors have been asked which is authoritative): non-commercial use only, published derived data must carry the notice and attribution, and the authors ask to be notified of use. Its provenance entry carries the licence, both citations and `attribution_required`.
- **Integrity:** the release is found through Zenodo's concept record; the CSV and YAML MD5 are verified against Zenodo's own checksums, so a truncated download fails instead of publishing.
- **Completeness (decision 22):** a year is published only if each of CO₂, CH₄, N₂O and the F-gas basket has **emission-weighted coverage ≥ 98%** (the share of the previous year's emissions still reported) and the national total is within **±15%** of the prior year. Emission-weighted rather than area-count because F-gas reporting drifts from 169 to 151 areas over 2017–2024 while the missing areas hold ~0.04% of emissions. Calibrated over 1751–2024: every gas ≥ 99.96%, total year-on-year −9.2% (1945) to +9.9% (1920). v2.8's 2025 fails (CH₄ 2.0%, N₂O 0.1%, F-gases 0.0%, total −28.3%) and is excluded. A failing year followed by a passing one raises; more than one trailing year trimmed raises a deviation.
- **Consistency check:** the per-gas sum (CO₂ + CH₄×28 + N₂O×265 + F-gas basket) must reproduce PRIMAP-hist's own Kyoto basket within 0.5% (v2.8: −0.18% … +0.21%).
- **Scope:** national emissions excluding LULUCF **and excluding international aviation/shipping** (not in the dataset); no world aggregate in the file, so the world total is the sum of areas.

### Harmonized layer (`harmonize.py`, `derive.py`)

One key (integer calendar year, unique per indicator), one unit and one **scope** (global / country) per indicator, explicit nulls (nothing is interpolated), and a link from every indicator to its source series' provenance. `indicator_catalog.json` lists every indicator: id, name, unit, kind (`level` / `cumulative` / `anomaly` / `uncertainty` / `derived`), its own coverage, provenance link, and for derived ones the baseline year, formula and the baselines that were excluded (with why). The API reads these tables; it never recomputes them.

- **Level** series get year-on-year %, a **trailing** 5-year mean (null until 5 consecutive observations; trailing so it never uses a later year) and an index for each allowed baseline: 1990, 1970, pre-industrial (= 1850) — defined only where the baseline value exists and is > 0.
- **Cumulative** series are never indexed or averaged. **Anomalies are never indexed** (the 1850–1900 anomaly is −0.13 °C in 1850, so "= 100" is meaningless, and a year-on-year % of an anomaly is undefined); they keep both native references and the interval, and get the trailing 5-year mean only. Every derived entry inherits its base's description and caveats, and every provenance link carries the source's checksums and URLs.
- Country scope is deliberately small: PRIMAP total, per-gas and cumulative per area.
- **No dense pandas reshapes anywhere in this layer** — see the environment note below.

### Pairing (`pairing.py`) — correlation-ready aligned series

```python
from pipeline.pairing import load_harmonized, align_pair
h = load_harmonized()                       # reads data/climate/{indicator_catalog.json, harmonized_*.csv}
frame, meta = align_pair(h, "owid_co2_world_cumulative_mt", "temperature_anomaly_1850_1900_c")
```

`frame` has columns `year`, `<a>`, `<b>` and only years where **both** series have a value (no interpolation). `meta` carries both indicators' catalog entries (unit, kind, coverage, **provenance link with release / licence / checksums**, caveats), the requested / common / used ranges, **every omitted year with its reason** (`a missing` / `b missing` / `both missing`, within the requested range), `interpolated: false`, and a standing note that co-movement is interpretive context, not proof of causation. Phase 1.3's co-trends, regressions and composition outputs are built on this.

Refused, with a clear error: pairing an indicator with itself; a **global** with a **country** indicator (country pairs need one named `geography` shared by both — country emissions are never paired with the global temperature line, §1.3.4); `uncertainty` series (they describe a series, they are not one); an empty range; and fewer than `min_overlap` (default 20) shared years — a correlation over a handful of years looks authoritative and means nothing. Derived indicators pair too, and the common range follows their own coverage (a trailing 5-year mean starts four years into the record).

### Headline regression (`correlation.py`, stage `correlate`)

A derived stage after `harmonize` (`python -m pipeline.run --source correlate`, and inside `--source all`) writing `data/climate/correlation_headline.json`, which the API (Phase 1.4) only reads. **Deterministic** — the only random draw is the bootstrap, with a fixed, recorded seed.

- **Headline (decision 40):** OLS of the Berkeley Earth anomaly (1850–1900 reference) on cumulative **total anthropogenic CO₂ since 1850** (OWID fossil + cement incl. international transport, plus land-use change). Slope in °C per 1,000 GtCO₂ (also per 1,000 GtC, the IPCC's unit), R², and **Newey–West (HAC)** standard errors with a 95% CI — plain OLS errors are too narrow because the residuals are autocorrelated (lag-1 ≈ 0.55, Durbin–Watson ≈ 0.9). Today: **0.520 [0.480, 0.559], R² 0.903, n = 175.**
- **Secondary, labelled variant:** the same regression on fossil + cement CO₂ alone (**0.797 [0.752, 0.843]**). Never hidden.
- **IPCC AR6** TCRE range (0.27–0.63, best estimate 0.45) is carried in the output with a `vs_ar6` verdict (inside the range? CI overlaps? ratio to the best estimate), so the comparison is against an uncertainty range.
- **Published sensitivities, as measured:** the CI under HAC bandwidths 4 / 8 / 16 (the default is floor(1.5·n^(1/3)) = 8); the slope by **estimation window** (start 1850 / 1900 / 1950 / 1970 — the only start years the API will accept, since outputs are precomputed; the headline slope *rises* with later starts, away from the IPCC value, and the UI says so); and the **land-use sensitivity** (land-use CO₂ × 0.7 / 1.0 / 1.3 → 0.583 / 0.520 / 0.468).
- **Stability check (Phase 1.3b, decision 34)** — a `stability` block on each variant. A **moving-block bootstrap of the residuals** (predictor held fixed; 2,000 resamples, 10-year blocks, **fixed seed 20261002 recorded in the output**, so it is identical run to run), distinct from the HAC interval, with the block-length sensitivity (5 / 10 / 20 / 30 years) and the HAC interval alongside; and **decade holdouts** (fit on the years before 1980 / 1990 / 2000 / 2010, predict the rest: train slope, RMSE, MAE, mean error, and the RMSE of just predicting the training-period mean for context). **Blocks are built only from calendar-consecutive years** (`align_pair` drops a year missing from either series, so row-based blocks could span a gap; with no gaps the draws are identical to an unconstrained bootstrap, so seeded results do not change). A block length the paired data cannot support is listed under `block_length_unavailable` with the reason, and if the primary 10-year length cannot be formed the variant is unavailable. Each variant carries a `contiguous` flag; **a calendar gap raises a deviation, because the Newey–West lags count rows** and so treat the rows either side of a gap as consecutive. A pairs bootstrap is deliberately not used: on a trending cumulative x it resamples samples with little x spread. Checked on simulated data with a known slope: the interval covers it 92% of the time (nominal 95%). A generated plain-language `summary` states the numbers; **no pass/fail label is produced**. Today (headline): bootstrap **[0.473, 0.568]** vs HAC [0.480, 0.559]; holdout at 2000: slope 0.466, RMSE 0.174 °C against 0.956 °C for the earlier average. **Note the holdout error is larger for the headline than for the fossil-only variant at every split** (RMSE 0.229 / 0.203 / 0.174 / 0.164 against 0.150 / 0.135 / 0.126 / 0.126): the land-use term improves the definition, not the out-of-sample fit; the UI should say so.
- **Land-use trade-off copy and weight scan (decisions 41–42).** The headline carries `fit_quality_note`: the owner-directed copy on the land-use trade-off, **generated from the holdout and R² numbers** (split 2000) so the UI, the agent and the docs quote identical figures. The wording follows the numbers — "a larger / smaller / similar error than the fossil-only variant" (within 10% is similar), the "cannot say whether that reflects land-use measurement uncertainty or something else" sentence only when the error is larger, and "In-sample, both variants fit the historical record almost identically (R² 0.903 vs 0.909); the difference appears specifically in out-of-sample prediction" only when the R² values are within 0.01. It never asserts a cause. Today: *"…a larger error than the fossil-only variant (0.17 vs 0.13 °C for 2000-2024)…"*. `land_use_weight_scan` (headline only) shows how the slope and the 2000-split holdout error respond to the weight on land-use CO₂ (0 = the fossil-only variant, 1 = the headline): holdout RMSE 0.126 / **0.095** / 0.111 / 0.136 / 0.174 / 0.206 °C for weights 0 / 0.25 / 0.5 / 0.7 / 1.0 / 1.3 — U-shaped, which is why the cause is not asserted. It is published to show the shape, **not to choose a weight** (a weight picked to minimise it would be tuned to the holdout). Both feed the "How this number was derived" section.
- **Recent all-gas relationship (Phase 1.3c-i, decision 35)** — a **separate output, `correlation_all_gas.json`** (never mixed into the headline file): the same anomaly regressed on cumulative PRIMAP-hist total GHG (CO₂-equivalent, AR5 GWP-100) from 1970 to the last complete PRIMAP year, with the same HAC interval, bootstrap, holdouts and gap handling. **It is never called TCRE** (not in any field, caveat or note — a test scans the file) and **has no IPCC comparison and no per-GtC figure**: the AR6 range describes CO₂ only. Its caveats say why it is a different thing: all gases, national totals (international aviation/shipping and land-use excluded), a short window, a steadily rising cumulative series strongly correlated with time, and CO₂-equivalent weights that treat short-lived methane as if it accumulated. Years PRIMAP-hist excludes as incomplete are listed (2025 today), the PRIMAP-hist licence (CC BY-NC-SA 4.0: non-commercial, share-alike) and citation travel in `attribution`/`caveats`, and the Berkeley vintage caveat is attached. Today: **0.579 [0.533, 0.626] °C per 1,000 GtCO₂e, R² 0.917, n = 55** (1970–2024; HAC lags 5; residual autocorrelation only 0.15); bootstrap [0.539, 0.619]; the 1980 holdout is unavailable (10 training years), 1990 / 2000 / 2010 give RMSE 0.172 / 0.129 / 0.114 °C. The window grid is clipped to 1970+ (one window). Its failure is independent of the headline's: if it is unavailable the headline files are untouched, and vice versa.
- **The slope does not depend on where the cumulative starts** (a constant added to x moves only the intercept), so the 1750-based fossil cumulative and the 1850-based total are comparable.
- **Caveats and attribution travel in the file:** plain-language "not a complete climate model", the methodology copy (decision 40), the OWID-World-vs-national-sum denominator statement (decision 15), the land-use uncertainty and licence note, the Global Carbon Project citation format, and the **Berkeley Earth vintage caveat** ("based on Berkeley Earth file vintage [Last-Modified date]; a possible ~0.1 °C discrepancy … has not yet been reconciled") which stays until `vintage_reconciled: true` is set on the `berkeley_earth` entry of `source_notices.json`.
- **Missing inputs** give explicit nulls (requirement §1.5): each variant is judged on **its own** inputs (the fossil-only secondary survives the land-use inputs being absent, and the headline survives the fossil one being absent), an unavailable variant is `null` with `<variant>_unavailable_reason` and a deviation, and **the output is always rewritten** — a missing/invalid harmonized layer or a refused pairing (e.g. fewer than 20 shared years) replaces the previous file with nulls and a reason instead of raising and leaving a stale regression in place. The metadata (method, methodology, definition, vintage, attribution, caveats, per-input availability) is complete in every case: it comes from `provenance.json` and module constants, not from the catalog having loaded. A non-positive slope, a CI that does not bracket the slope, or a non-finite statistic raises a deviation.
- **Run order and dependency (`run.DEPENDS_ON`):** in `--source all`, `correlate` is **skipped** — recorded as a failure with the reason, so the push alert fires — when `harmonize` raised in the same run, because it would otherwise build a fresh-looking result (new `generated_at`) from the previous run's catalog. Its last good output is left untouched, consistent with the harmonized tables it was built from. `harmonize` itself is deliberately *not* gated on the sources: it merges several independent sources, a partial update is normal, and each source's age is in its provenance. `--source correlate` on its own is never gated. A malformed harmonized layer is a clear `ValueError` at load time — a table missing a required column, a catalog entry missing `id`/`name`/`unit`/`kind`/`scope`, or a catalog of the wrong shape — handled like any other unavailable input (explicit nulls). A degenerate predictor (no variation over the paired years) makes only that variant unavailable. **As a structural guarantee, anything unexpected** while loading or inside a variant is also turned into explicit nulls + a deviation (with the traceback logged), so no exception type can leave a previous regression in place as current.
- statsmodels is imported from its submodules, never `statsmodels.api` (broken by scipy 1.17; see `requirements.txt`).

### GHG composition (`composition.py`, stage `composition`; Phase 1.3c-ii, decision 36)

A derived stage reading PRIMAP-hist's global composition series (already restricted to years that passed the completeness test) and writing `correlation_composition_annual.csv` (**the long file**: year, gas, gas name, MtCO₂e, share %, one row per year and gas — a selected-year treemap or stacked bar is a filter on it, not a second computation) and `correlation_composition.json` (basis, units, coverage, per-year `gases_included`, the reconciliation, caveats, attribution). Today: **1750–2024; 2024 = CO₂ 75.1%, CH₄ 16.7%, N₂O 5.4%, F-gases 2.9%.**

- **Explicit nulls, never an invented zero.** A gas with no value for a year is empty in the file and absent from that year's `gases_included`; shares are then over the gases included (stated, not hidden), and a missing CO₂, CH₄ or N₂O is a deviation (F-gases, reported later historically, are a note). **A zero PRIMAP-hist itself reports stays a zero** — F-gases are 0.0 in 1750 and positive from 1850 in the real data, and nothing is null there today.
- **Shares sum to 100** (±1e-6, enforced on the unrounded values; the published CSV is rounded to 8 decimals so it satisfies the same tolerance). **The gases are reconciled to PRIMAP-hist's own national total each year** (`residual_pct`, ±0.21% at most today, deviation beyond ±1%).
- **Early history is flagged from the data**: in 1750 CH₄ is 95% of the CO₂-equivalent total and CO₂ only 1%, because national CO₂ excludes land-use change while agricultural methane is included, so the earliest decades are a reconstruction, not an observation. The caveat is generated only when CO₂ is not the largest share in the first year, and it names whichever gas actually leads. In `--source all` the stage is **skipped when `primap_hist` failed in the same run** (`run.DEPENDS_ON`; it reads that artifact as a whole), so a fresh-looking composition is never built from stale inputs.
- **Provenance must prove completeness**: the recorded `[first, last]` coverage is required (missing or malformed means nothing is published) and a year outside it is a deviation. **Every published year must be usable and reconciled**: a year with no gas values (or a non-positive total), or with a missing/zero/non-finite national total, is invalid input, not a skipped year — skipping would leave a gap in a series whose coverage claims to be contiguous, and a year without a valid total could not be reconciled. A missing/invalid input, a gap in the years or malformed provenance **rewrites both files** with explicit nulls (header-only CSV, JSON with `unavailable_reason` and the full caveats/attribution) and a deviation, never a stale composition. Not gated on `harmonize` (it reads the source series directly).
- The PRIMAP-hist licence (CC BY-NC-SA 4.0: non-commercial, share-alike), the citation and the AR5 GWP-100 basis (CH₄ 28, N₂O 265) travel in the JSON.

### Country cumulative share (`country_share.py`, stage `country_share`; Phase 1.3c-iii, decision 37)

A derived stage writing `correlation_country_share.csv` (**the long file**: country ISO3, year, source, gas scope, cumulative, share %) and `correlation_country_share.json` (per combination: coverage, the denominator and its reconciliation, countries with gaps, the latest top emitters; plus caveats, attribution and country names). Three combinations: **`owid_co2` × `co2`** (OWID fossil + cement), **`primap_hist` × `co2`** and **`primap_hist` × `total_ghg`**. Today: ~95k rows; in 2024 the top of each is USA 24.1% / 24.0% / 20.5%, China 15.8% / 15.9% / 15.6%, Russia 6.8% / 7.0% / 6.6% (OWID-CO₂ / PRIMAP-CO₂ / PRIMAP-total).

- **Share = a country's cumulative emissions ÷ the sum of all countries' cumulative emissions** (the national sum: ISO3 countries; international aviation/shipping and non-ISO aggregates excluded), so shares sum to 100 (1e-6; the published file is rounded to 10 decimals to stay inside that). This is deliberately **not** the World series used by the headline regression — the national sum is **2.49% below** it in cumulative CO₂, which is the international aviation and shipping share (decision 15), and the JSON states the difference.
- **Cumulative from the source's first year (1750), published from 1850**, so pre-1850 emissions count. A country has rows from its first observation; an absent row means no emissions recorded yet (a cumulative of zero).
- **A missing year inside a country's record counts as zero and is listed, never interpolated** (47 OWID countries, all in the 1800s — a rough interpolation puts them at about 0.015% of the cumulative total); a series that ends early stops growing and is listed (Antarctica after 2007 in PRIMAP-hist). The denominator is the sum of the same cumulatives, so shares stay consistent.
- **Reconciled to what is already published**: the OWID sum equals the cumulative of `owid_world_co2_annual.national_sum_mt` (exactly), the PRIMAP-hist sums equal the cumulative of the global composition series (to 4e-8, from rounding in that file); a mismatch beyond 1e-6 is a deviation. An earlier worry — that dropping non-ISO entities such as the USSR would understate the denominator historically — was checked and does not apply: OWID allocates those emissions to the successor states, and World equals the ISO3 sum plus international transport to within 0.0% in every sampled year (189 Mt of 1.85 million are unaccounted for: Kuwaiti oil fires, Kosovo, Ryukyu Islands).
- **No attribution is claimed** (the caveat is in the file and in `note`): shares describe where emissions occurred, not responsibility for warming, and no country series is ever regressed against the global temperature series. Territorial (production-based) emissions, not adjusted for trade.
- **Each source fails independently** (explicit `available: false` with a reason, the other source unaffected), and both files are always rewritten, so a stale OWID share cannot survive an OWID failure. In `--source all` the stage is skipped when `owid` or `primap_hist` failed in the same run (`run.DEPENDS_ON`).
- The working frame is built from arrays: on Python 3.14 even `DataFrame.assign` on a freshly subset frame trips pandas' chained-assignment warning (a false positive), and no dense pandas reshape is used.

### OWID notes

- **Land-use CO₂ and total anthropogenic CO₂ (decision 40).** The OWID step also keeps the World `land_use_change_co2` column (Global Carbon Project via OWID, 1850+; same file, no new source) as `land_use_change_co2_mt`, and publishes `total_co2_incl_luc_mt` = fossil + cement + land-use. Harmonize exposes `owid_luc_co2_world_mt`, `owid_total_co2_world_mt` and **`owid_total_co2_world_cumulative_mt` (cumulative from 1850) — the headline regression's X-variable**; the 1750-based fossil `owid_co2_world_cumulative_mt` is the labelled secondary. A missing/short/gappy land-use column is a deviation, never a crash (the fossil series is unaffected). **Licence/attribution (recorded verbatim in provenance as `land_use_license_note`):** *"Land-use CO2 data originates from the Global Carbon Project via OWID. No formal license (e.g., CC BY) is stated on the Global Carbon Project's data page; use is conditional on citing the original source per their stated terms. The required citation is included in this platform's data attribution. No non-commercial, no-derivatives, or share-alike restrictions were found."* — the GCP citation format is in provenance (`required_citation_format`) and every output using the series must carry it. Land-use CO₂ is modelled (±0.7 GtC/yr ≈ ±2.6 GtCO₂/yr, 1σ), so the headline slope is published with a land-use sensitivity.
- **No download here.** The refresh job (`ops/ghg-data-refresh.sh`) already backs up, downloads and validates the OWID file (the week-1 notebook is the validation authority) and restores the backup on failure. `owid.py` takes the file as it stands afterwards, records provenance (path, sha256, rows, coverage, licence, citations; `retrieved_at` is the file's modification time) and publishes the small normalized World series.
- **World series (decision 15):** `co2_mt` is OWID's World total **including international aviation/shipping** (the TCRE regression X-variable); `national_sum_mt` sums the ISO-coded countries (the country-share denominator); `international_transport_mt` is OWID's aviation + shipping rows. They reconcile (2024: within 0.02%); a gap above 1% is a deviation.
- **Completeness (trailing years only):** emission-weighted country coverage ≥ 98% **and** World CO₂ within ±15% of the prior year. The last four years are checked and everything from the **first** failing year onward is trimmed (two consecutive partial years would otherwise let the second look complete relative to the first); more than two raises. Full-history year-on-year isn't tested: the World series swings −27%…+34% in 1803–1830.
- **Deviations:** file older than 45 days (the refresh job has stopped), latest year more than two years behind, row count down >5% vs the previous run, World `cumulative_co2` gaps.

### Notifications and the refresh job

`pipeline.run` writes `data/climate/last_run.json` plus `last_run.priority` / `last_run.title` / `last_run.message` (urgent = a source failed outright, high = deviations from norm, default = clean). The refresh script reads those three files and appends them to its ntfy push. The versioned script and the monthly launchd plist, and how to deploy them to the Mac Mini, are in `ops/` (nothing is deployed by merging).

### EDGAR notes — SHELVED for publication

EDGAR is **not** an active source: it is excluded from `--source all`, writes only to `data/internal/edgar/` (which the API never reads), and must not feed any public surface. Reason: the fuel-combustion CO₂ in EDGAR (88.5% of its CO₂ and 65.5% of its total GHG in 2023) is IEA data licensed CC BY-NC-ND 4.0; ND bars sharing the transformed series this pipeline produces, and IEA permission has not been obtained. It is kept to cross-check the active total-GHG source locally, and for re-activation if permission is obtained and its sector detail proves worth it (`ENHANCEMENTS.md` Release 21, decision 20).

- The gas split is built from the per-gas files (fossil CO₂; CH₄ and N₂O × AR5 GWP-100 of 28 / 265; F-gases from the AR5g CO₂e file), summed, and **reconciled against the combined AR5 workbook** every run. The per-year residual is in the output and provenance; a global residual beyond 1% in a year where all four gases exist raises a deviation.
